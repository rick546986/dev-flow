② 每件用途

元件用途
dev-talk@local訪談引導 skill(版本以其 plugin.json 實值為準;含受影響面清點、五掃複核、⚠️ 高影響決策標記)+ 視覺版殼檔。單一正本,兩帳號同時生效。
dev-flow@local流程路由器 + dev-setup 健康檢查 + guard hook。hook 隨 plugin 啟用自動掛載(不再寫進 settings.json)。
devtalk-guard.sh任何 Edit/Write 後檢查:目標路徑含 skills/dev-talk/ 才動作 → 洩漏掃描(下游階段字眼)→ 命中 exit 2 把錯誤直接回饋給模型要求立即修正。其他路徑靜默放行。
dev-setup skill專案安裝器(install:docs/dev 模板 + devflow-contract.json 散發(版本握手契約)+ evidence gauntlet 散發到 docs/dev/tools/(chmod +x + 兩道可執行驗證)+ .claude/rules/ 骨架 + gitignore;upgrade:只覆蓋 README/_templates/tools/(gauntlet)/devflow-contract.json,絕不動已產 feature 檔(B-2 新規:改採三方比對 —— 上游舊 blob / 上游新 blob / 本地現況,本地客製過的檔逐檔徵求使用者同意才覆蓋,不再整批靜默覆蓋;見 skills/dev-setup/SKILL.md upgrade 節);未識別的外部 workflow artifacts 全數保留)+ 健康檢查(項目數與編號以 skills/dev-setup/SKILL.md 的 check 節為準,含 gauntlet 散發、版本握手+doctor、gate twin 產生器散發等項)。
執行守衛
(devflow-exec + guard + prebash + postbash)		Stage 6 起手 devflow-exec.sh start <slug>:驗 4-spec=approved、逐 T 驗 Covers/Files/Verify/Blocked-by、把 Git root 相對 Files 正規化為 scope。scope 外真實髒檔先拒啟(不再 baseline);只有 .DS_Store/._*/Thumbs.db/__pycache__//*.pyc 是 ambient。旗標存在時:PreToolUse 擋改 4-spec/1/2/3(契約防篡改+L2 強制停修審)、擋讀 1/2/3(圍欄②)、擋 scope 外寫入(附 L1/L2 提示);PostToolUse Bash 每次指令後 git status 對照 scope,shell 寫入幾秒內被抓。L1 合法出口:allow <file> --reason(留 log + 提醒記 D-n)。stop 撤旗標 → 全部沉睡,其他工作零干擾。另支援 Stage 6 T 級並行(5-tasks execution.mode: parallel 才啟用):parallel-init/wave 系列子命令 + start --task T-n 任務樹武裝(每 T 一 worktree,同 Wave 同 Base)、Mechanical Gate 14 項機械檢查、上游 candidate 被替換自動標 INVALIDATED_BY_UPSTREAM;doctor = 契約握手 fail-closed(見 ②b)。
dev-run 引擎派工者(opus/fable5 主對話,不寫碼)逐 T:haiku 執行 → sonnet fresh review → 錯誤升階(haiku→sonnet→opus,同層最多兩次;FAIL 先分類 SPEC/ENV/IMPL/UNKNOWN 再路由,同 T 總嘗試上限 4);升階史記 6-notes「執行軌跡」→ 7-review.html 執行記錄表。逐 attempt 事件經 devflow-exec.sh event 寫入 Attempt Ledger(devflow-obs,agent_event schema 1.1),執行軌跡/執行記錄由 devflow-obs.sh derive 衍生禁雙寫(sequential v1 無 run_id → 事件步 N/A,禁虛構)。偏差 L1 保守+記+續走,L2 才停(field guide 模式)。

②b 版本握手(devflow-contract.json + doctor)

  • 契約正本:母版 ~/dev/dev-flow/devflow-contract.json; dev-setup install/upgrade 散發副本到專案 docs/dev/devflow-contract.json (check 第 10 項驗存在 + 與母版 diff 無差異)。
  • doctor 找檔順序:--contract <path> 明示 → $DEVFLOW_CONTRACT → 專案 docs/dev/devflow-contract.json; 缺件必 fail-closed,不靜默退回舊行為。
  • doctor 比對契約與 hooks/runtime-capabilities.json(runtime 能力宣告); verdict INCOMPATIBLE = 刻意擋下,不得繞過或改綠 —— 修它列出的不相容項、或升級 runtime/方法論後重跑;舊 sequential 專案標 legacy compatibility mode。

④ 手動檢查指令

下列 PLUGIN 為安裝後的實際路徑,版號依安裝而定(見 docs/PLUGIN.md); Windows 對應 %USERPROFILE%\.claude\plugins\cache\dev-flow\dev-flow\<version>。

PLUGIN=~/.claude/plugins/cache/dev-flow/dev-flow/<version>

# plugin 結構 + 啟用
jq '.plugins[].name' "$PLUGIN/.claude-plugin/marketplace.json"
jq '.enabledPlugins | with_entries(select(.key|test("dev-")))' \
  ~/.claude/settings.json ~/.claude-team/settings.json

# 執行守衛全情境自測(可重跑;自建 temp 假 repo 跑動態發現的案例後自清)
"$PLUGIN/hooks/selftest.sh"        # -v 看逐案明細

# devtalk-guard 單案自測(期望:exit 0;dev-talk 併入單一 plugin 後 skill 路徑同一 PLUGIN 根)
echo '{"tool_input":{"file_path":"'$HOME'/.claude/plugins/cache/dev-flow/dev-flow/<version>/skills/dev-talk/SKILL.md"}}' \
  | "$PLUGIN/hooks/devtalk-guard.sh"; echo exit=$?

# 盲掃(掃整個 dev-talk skill 目錄,含 SKILL.md description;期望:無輸出;
# dev-talk 併入後不再有獨立 plugin.json,洩漏風險全落在這份 SKILL.md)
grep -rniE "dev-flow|2-decision|4-spec|5-tasks|7-review|G1|G2|G3|gate|twin|pipeline|規劃|plan" \
  "$PLUGIN/skills/dev-talk/"

# 掛載驗證(自測只證 script 邏輯,不證掛載 —— 這條才驗掛載)
jq -e '.hooks | to_entries[] | .key as $e | .value[] | .matcher' \
  "$PLUGIN/hooks/hooks.json"    # 條數以 skills/dev-setup/SKILL.md check 節為準

# evidence gauntlet 散發驗證(在採用專案內跑;install 步 6 / check 第 9 項的兩道)
bash docs/dev/tools/devflow-evidence-gauntlet.sh       # 期望:印 usage 且 exit 2
bash docs/dev/tools/devflow-evidence-gauntlet.sh \
  ~/dev/dev-flow/scripts/fixtures/evidence-gauntlet/good-evidence.md   # 期望:exit 0

# 版本握手(在採用專案內跑;check 第 10 項)
"$PLUGIN/hooks/devflow-exec.sh" doctor   # 看 verdict;INCOMPATIBLE 不得繞過

⑤ 停用 / 移除

停用:兩帳號 settings.json 的 enabledPlugins 把 dev-talk@local / dev-flow@local 設 false(hook 隨 plugin 一起停)。徹底移除:再刪 plugin 目錄與 marketplace.json 內兩個 entry。

⑥ 界線(誠實聲明)

  • 內容硬檢,非權限硬擋 —— dev-talk 的讀寫白名單仍是 prompt 級圍欄(hook 無法得知目前 session 是不是 dev-talk,全域擋寫會誤傷其他工作)。
  • 守得住:dev-talk 的檔案(SKILL/殼檔)被任何 session 改出洩漏字眼 → 立即被抓、回饋要求修正。
  • 守不住:討論進行中的行為偏移(靠 dogfood 盯破盲徵兆)、使用者自己說出下游資訊(設計上不擋)。
  • 執行守衛的殘餘界線(red team 確認,刻意不修):①start 前把 5-tasks Files 寫寬 → 快照照收(緩解:start 會對 src/、docs/ 這類過寬 scope 出警告;5-tasks 若已 commit 過,G3 diff 看得出加寬)②stop → 改 4-spec(保留 status: approved 字串)→ start:目前只驗字串不驗簽章(根治需 G2 核准時寫入內容 hash,列為後續)③shell 圍欄是關鍵字比對,能擋隨手 cat,擋不了刻意混淆 ④跳過步 0 不建旗標 = 全套沉睡。此守衛是紀律輔助工具,不是安全沙箱 —— 對手設定為「想抄捷徑的執行 agent」,不是惡意攻擊者。
  • 改 plugin 內容後,執行中的 session 要 /reload-plugins 才吃到新版。
