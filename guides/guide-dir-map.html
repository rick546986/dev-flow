母版目錄樹

預設只看到 dev-flow/ 底下第一層。摺疊時仍是一棵樹。藍色資料夾名可點，點開才接子層；子層一樣用 ├─ │ └─。右邊 why 說這是什麼、何時用、跟誰有關。

dev-flow/方法包根。規則在 README，技能在 skills/；三邊 plugin 只是薄殼，都指回這裡。
├─ skills/方法包正本，三邊 plugin 整棵掛這裡。要看流程從這點下去，不要從 hooks／scripts 找規則。
│ ├─ dev-talk/第 1 站討論技能。獨立 session、全盲下游；產出 1-discussion.md，不進 G1。
│ │ ├─ SKILL.md討論站入口。觸發才載全文；只留盲原則與摘要，下一跳看 graph.yaml。
│ │ ├─ graph.yaml討論站下一跳正本。本機游標不進 Git；改 hop 先改這份再對 nodes/。
│ │ ├─ html-shell.html掃頁殼。S10 用來包 1-discussion.html，不准手寫、不准拿去充審頁。
│ │ └─ nodes/一 hop 一檔，順序跟 graph.yaml 的 next。點開才看開場到收尾。
│ │ ├─ N1-start.md討論開場：建 session、鎖盲原則與讀寫白名單。下一跳才定範圍，這裡不寫 1-discussion.md。
│ │ ├─ S0-scope.md定本輪要談什麼、不談什麼。接開場、交給掃現況，仍不寫檔、不碰下游階段。
│ │ ├─ S1-survey.md掃現況事實：規格、程式位置、數據。只記查過的，不把推測寫成 Context。
│ │ ├─ S2-world.md補真實世界怎麼做完這件事（人、繞過、例外）。這是後面觸發判定與 Operational Context 的原料。
│ │ ├─ N3-probe.md追問不知道的事。可 talk_turn／propose，仍不准寫 md、不准寫程式。
│ │ ├─ S4-accept.md把 Goal 翻成使用者視角的驗收雛形。這是 4-spec Scenario 的種子，還不做決定。
│ │ ├─ S5-diverge.md把不知道變成問題清單。發散、不收斂，下一跳才盲檢下游。
│ │ ├─ S6-blind.md盲檢：討論 agent 不准知道後續站。防止這輪已經在寫方案或任務。
│ │ ├─ N9-write-md.md覆寫本 feat 的 1-discussion.md。只准這一份，十節齊、無佔位符。
│ │ ├─ S8-review.md自檢剛寫的討論檔。可改同一份 md，不准另存、不准寫程式。
│ │ ├─ S9-terms.md對過詞彙與三態 Open Questions。全數落入已解／帶假設／移交才算討論完。
│ │ ├─ S10-html.md掃頁：用 html-shell 產 1-discussion.html 六件套。不要跟目錄樹或審頁三框搶槽。
│ │ └─ N13-end.md討論收尾：md 與掃頁都在就停。不另存第二份討論檔。
│ ├─ dev-flow/第 2–7 站路由器。定位 stage 後接手該站；第 6 站會再載 dev-run。
│ │ ├─ SKILL.md第 2–7 站入口與 lane／gate 摘要。細節以 README 為準，各站 hop 在 stage*/。
│ │ ├─ stage2/收斂站，出口 G1。把討論收成方向；過了才寫規格或做原型。
│ │ │ ├─ graph.yaml第 2 站下一跳正本。九個 hop，從接手寫到 G1。
│ │ │ └─ nodes/一 hop 一檔。生方案、壓測、寫 2-decision、送 G1。
│ │ │ ├─ N1-handoff.md從已核准的 1-discussion 接手。只讀討論檔，確認能收斂再往下生方案。
│ │ │ ├─ S1-approaches.md並排生 2–3 個方案。還不壓測，下一跳才定案。
│ │ │ ├─ S2-stress.md壓測定案：挑一個方向。G1 要審的就是這裡定下來的東西。
│ │ │ ├─ N3-write-md.md寫 2-decision.md。單產物，不准另存第二份決策檔。
│ │ │ ├─ S4-oc.md寫 Owner Call。人要裁決的點放這裡，不要埋在方案敘事裡。
│ │ │ ├─ S5-adr.md該抄 ADR 的決策抄到 docs/adr/。不是每案都有，有不可逆方向才寫。
│ │ │ ├─ S6-selfcheck.md交 G1 前自檢：方案、OC、ADR 對得上 2-decision.md。
│ │ │ ├─ N7-g1.md送 G1。方向核准 + OC 全裁決才過，作者不能當 approver。
│ │ │ └─ N8-end.md第 2 站收尾。過 G1 才往規格或原型走。
│ │ ├─ stage3/原型站，可 skip。開場先觸發判定；0 命中走 N-skip，有命中才實驗。
│ │ │ ├─ graph.yaml第 3 站下一跳正本。分叉用 next + fork_required，禁止 via。
│ │ │ └─ nodes/一 hop 一檔。含 skip 與實驗兩條，不要漏 fork 那側。
│ │ │ ├─ N1-trigger.md先做觸發判定。0 命中走 N-skip，有命中才進 S0-question，禁止 via。
│ │ │ ├─ N-skip.md觸發 0 命中：本站跳過。不寫 3-prototype.md，直接結束。
│ │ │ ├─ S0-question.mdfork：真的要做原型時定義要回答的疑問。跟 N-skip 互斥。
│ │ │ ├─ S1-experiment.md做 throwaway 實驗。程式進 throwaway branch，不准進 main。
│ │ │ ├─ S2-evidence.md收實驗證據。沒證據就不要寫結論。
│ │ │ ├─ N3-write-md.md寫 3-prototype.md。涉互動要有可操作 Demo 與人填 verdict。
│ │ │ ├─ S3-writeback.md答案回寫 2-decision.md。原型站的出口是決策檔，不是另開一條規格。
│ │ │ ├─ S4-close.md原型收尾自檢。frontmatter 與回寫對得上才往結束走。
│ │ │ └─ N5-end.md第 3 站結束。skip 或做完都走這裡，再進第 4 站。
│ │ ├─ stage4/規格站，出口 G2。R/S/DD/Profile 寫死；過了才切任務。
│ │ │ ├─ graph.yaml第 4 站下一跳正本。從接手列 R 寫到 G2。
│ │ │ └─ nodes/一 hop 一檔。反模糊三律在這裡落地，不是在任務站補。
│ │ │ ├─ N1-handoff.md從決策（與可選原型）接手寫規格。只帶討論的驗收雛形與 OC，不回引逐字稿。
│ │ │ ├─ S1-requirements.md列 R。每條要能往下長 S，禁止模糊詞與 TBD。
│ │ │ ├─ S2-scenarios.md展 S。一條 S 要能轉成單一測試，測試名會帶 S-id。
│ │ │ ├─ S3a-close.md收邊界：Non-Goals 與不做的例外寫死，防範圍蔓延。
│ │ │ ├─ S3b-profile.md填 Verification Profile。依 lane 填，G2 要審這張表。
│ │ │ ├─ S3c-stage3.md對帳原型：有 3-prototype 才核 Demo verdict，沒有就標 n-a。
│ │ │ ├─ S4-dd.md寫 Drafting Decision。規格寫作時的選擇記在這裡，G2 要全裁決。
│ │ │ ├─ N5-write-md.md寫 4-spec.md。openspec delta，單產物。
│ │ │ ├─ S5-gate.md機械關自檢：R/S/DD/Profile 齊了才准送 G2。
│ │ │ ├─ N6-g2.md送 G2。R/S 全審 + DD 全裁決，過了才切任務。
│ │ │ └─ N7-end.md第 4 站收尾。規格是後面實作唯一準繩。
│ │ ├─ stage5/任務板，無 G。把規格切成 T；人同意這張板才進實作。
│ │ │ ├─ graph.yaml第 5 站下一跳正本。切 T、填欄、產執行板。
│ │ │ └─ nodes/一 hop 一檔。Covers／Files／Verify／Blocked-by 都在這幾跳填。
│ │ │ ├─ N1-handoff.md從已核准 4-spec 接手切任務。實作者之後不准回讀 1/2/3。
│ │ │ ├─ S1-slice.md切 T：tracer-bullet 順序。每 T 要有 Covers，對得上 S。
│ │ │ ├─ S2-fields.md填欄：Files／Verify／Blocked-by 必填，給 devflow-exec 解析 scope。
│ │ │ ├─ S3-deps.md標依賴。Blocked-by 決定能不能平行，不要事後口頭講。
│ │ │ ├─ N4-write-md.md寫 5-tasks.md。這是第 6 站的工作單，不是進度日誌。
│ │ │ ├─ S4-selfcheck.md自檢每 T 的 Verify 與 Files。缺欄不准往下產執行板。
│ │ │ ├─ N5-twin.md產第 5 站執行板／審頁 twin。人看任務總表用，不改 hop。
│ │ │ └─ N6-end.md任務板定稿。無 G；人同意這張板才進實作。
│ │ ├─ stage6/實作站。守衛 + 逐 T；平行時另走 parallel 契約，不是這棵 hop 的另一張圖。
│ │ │ ├─ graph.yaml第 6 站下一跳正本。武裝、接手、逐 T、自檢、結束。
│ │ │ └─ nodes/一 hop 一檔。真正寫碼在 S2-tdd，前後是守衛與自檢。
│ │ │ ├─ N1-arm.md武裝執行守衛。沒 start 不准當第 6 站在跑。
│ │ │ ├─ N2-handoff.md核對 4-spec + 5-tasks + 6-notes。禁讀 1/2/3，缺東西回 G2。
│ │ │ ├─ S2-tdd.md逐 T：RED→GREEN→scope→Verify→獨立 review→PASS→commit。
│ │ │ ├─ N4-selfcheck.md實作自檢：每 T review PASS、改動 ⊆ Files 聯集。
│ │ │ └─ N5-end.md第 6 站結束。驗證另開第 7 站，不在這裡宣佈 G3。
│ │ └─ stage7/驗證站，出口 G3。reviewer 自建矩陣再親跑，不是複誦作者結論。
│ │ ├─ graph.yaml第 7 站下一跳正本。從角色防錨定寫到 Verdict。
│ │ └─ nodes/一 hop 一檔。現象、回歸、Fresh、走查都在送 G3 之前。
│ │ ├─ N0-role.md角色與防錨定：先自建矩陣，才准看作者 Self-Review。
│ │ ├─ N1-matrix.md自建 coverage matrix。reviewer 用 R→S→T 鏈對，不抄作者表。
│ │ ├─ S2-run.md親跑驗證。完成宣稱要附原始輸出或檔案:行號。
│ │ ├─ S2b-phenomena.md現象複驗。宣稱的畫面／行為要有證據，不能只看測試綠。
│ │ ├─ S2c-integration.md整合回歸。本次 S 全綠還不夠，既有測試也要綠。
│ │ ├─ S2d-fresh.mdFinal Fresh：乾淨環境再跑一次，防本機髒狀態。
│ │ ├─ S2e-walkthrough.md操作走查。人真的點過主路徑，不是只看 log。
│ │ ├─ N3-axes.md雙軸審：Standards + Spec。兩邊都過才往下對作者。
│ │ ├─ N4-author.md對照作者 Self-Review。找漏，不讓作者的表取代 reviewer 矩陣。
│ │ └─ N5-verdict.md寫 Verdict。G3 要本次 S + 回歸 + 現象 + Evidence 契約全過。
│ ├─ dev-run/第 6 站內部引擎。正常由 dev-flow 定位到 stage 6 時載入，不必當第二個指令學。
│ │ └─ SKILL.md整棵掛，裡面只有這份。haiku 寫碼、sonnet 審、錯誤升階，配 devflow-exec。
│ ├─ dev-setup/初裝／升級／修復。產品專案打一次，把方法包模板與工具抄進 docs/dev/。
