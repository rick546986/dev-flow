# N3-probe — 逐題逼問

## 進條件

MEMORY_SESSION_ID 已存在。步 0–2 已完成(slug / 已核事實 / 真實世界五份)。
游標在 N3,或剛從 S2-world 進來。
**已有 MEMORY_SESSION_ID 再進本節點,不得呼叫 talk start。**重跑是從 N3 跑到後續節點,不是再開一場。

## 讀什麼

白名單(長期記憶入口、`docs/specs/`、原始碼)、本場 turn、已核事實、真實世界五份。
不讀白名單外的文件類資料夾。

## 寫哪裡

只經 `dev-memory.py talk turn` / `talk propose` 登記本機輪次與候選。
turn / propose 不得直接改長期記憶檔。
不寫 `1-discussion.md`。不寫程式碼。不得 talk end。

## 做什麼

舊執行清單步 3(含 3a/3b)。每輪三律:
①一次只問一題、附推薦答案,同題多種解讀 → 列差異讓使用者選、**禁默選**;
②答後覆述推理鏈「因為(事實)→ 所以(推理)→ 結論」,接不上就說卡在哪、不要猜;
③**決定必問** —— 只有「已核事實」或新查證後回報過的才算事實,
**清單外的斷言 → 問使用者或標〔假設〕,禁默默當事實用**。
優先問會改變架構的題;關鍵決策追問一層(why/邊界/反例)。
新業務詞彙隨手記下(S9-terms 對帳)。

條件觸發(非每輪都會遇到):
- **3a. 前提被推翻**(觸發:已核事實或既有結論被新答案推翻)→ 立即核銷:
  已寫的 Context/真實世界五份/Goals/雛形/詞條逐段標失效並更新,才繼續。
- **3b. 發現實為多題**(觸發:當前題目其實含多個可獨立交付的子問題)→ 停,
  提議拆分:當前討論收斂到使用者選的子題,其餘各記一條 `[>]` 移交(附建議
  slug 名,留待另開討論),不併成一個大題。
跑 `${DEVFLOW_ROOT}/scripts/check-devtalk-graph.sh --write-cursor N3-probe "$MEMORY_SESSION_ID"`。

## 完成條件

連續兩輪無新問題、既有題全數落入三態,且你能複述問題/目標/邊界而不被糾正。
