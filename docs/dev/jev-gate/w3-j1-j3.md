## 1. P1-F2 J1（clarity first）

**做了什麼**

- 呼叫點在 Decide 入口，不在 dev-talk 裡（討論仍全盲下游）。`skills/dev-flow/stage2/nodes/N1-handoff.md` 在提煉決策點之前跑：

```
python3 ${DEVFLOW_ROOT}/scripts/devflow-jev.py handoff --gate J1 --slug <slug> ...
```

- `handoff` 是 `scripts/devflow-jev.py` 的子命令。雙閘門 live 時它呼叫**同一個檔案裡的** `run_ask`（也就是 `ask --gate J1`）。沒有第二個 HTTP client，沒有新的網路模組。
- 題組仍是 W1 的 `goal_clear`、`scope_clear`、`acceptance_clear`、`owner_call_pending`、`ambiguity`、`next`。`next` ∈ `START_DECIDE`｜`ASK_MORE`｜`NEEDS_OWNER_DECISION`。
- 弱維度只吃 `route_j1` 從三個 clarity noul 取出的 `weakest_dimension`。`j1_effect` 的參數沒有 probabilities，不能從 `next` 的分布逆推。
- `effect`：
  - `start_decide`：不要再問一次「夠清楚嗎」。
  - `ask_more`：停。主題句是固定人話（`policy.J1_THEMES`），並用 `assert_no_rubric_copy` 拒絕抄題組原文。`instruction` 要求新 session、完整 11 步、從 `S0-scope`／`S1-survey`／`S2-world` 重盤、N13 仍要人點頭。
  - `needs_owner_decision`：停。第 2 輪評估仍是 `ASK_MORE` 時，流程層改成這個，不開第三輪（`J1_ASK_MORE_MAX_ROUNDS = 2`，含本輪）。
  - `continue_existing_flow`：off、shadow、草稿（frontmatter 不是 `approved`）、逾時、傳輸失敗、組包失敗。既有 Decide 照走。exit 0。
- P0-9：packet 的 `quoted_context.source` 標成「S1 待重驗的 Log 材料，不是已核事實」。`source_facts` 只放機械句，不把 Goals 正文當已核事實。dev-talk 的 `N1-start`／`S0-scope`／`S1-survey`／`N13-end` 寫明重跑 S0–S2、不得靠讀舊討論省一輪、讀取白名單不是機械執行、人點頭不省。這些句子避開 dev-talk 盲原則字詞表。
- 同一份已評估討論（同一 `discussion_hash`）再跑 handoff 不打第二次 API。輪數記在 gitignored `.devflow/jev/state/j1-rounds.json`。

**結論**

- 失敗／逾時／沒開雙閘門 ≡ 沒啟用 Jev。
- 兩輪之後的 `ASK_MORE` 不會變成第三場討論。
- 帳本裡的 `route_taken` 仍是模型路由；第 2 輪的封頂是 handoff 的 `effect`，agent 跟 `effect`，不跟被封頂前的 `model_next`。

**證據路徑**：`scripts/devflow-jev.py`（`run_handoff_j1`）、`scripts/devflow_jev/policy.py`（`j1_effect`／`j1_theme`）、`skills/dev-flow/stage2/nodes/N1-handoff.md`、`skills/dev-talk/nodes/{N1-start,S0-scope,S1-survey,N13-end}.md`。
