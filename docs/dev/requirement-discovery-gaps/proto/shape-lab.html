形狀實驗室

用本 slug 的 Journey／範例教師對照，回答 Stage 2 留下的欄位形。一次一場。Pattern 已 lock（1A–8A），沒有第二套互動。

開場

這不是產品 UI。你要當 討論 agent / 收斂者 / Fast 實作者，看四個填法長什麼樣，並指出錯欄。

  1. Goals 只寫工作結果；構想進 Requested solution（未定案）。
  2. 發現題標「發現」、禁推薦；裁決題才可附選項／差異／推薦。
  3. disposition 一列 = 原文片段 + 五態去向 + 一句理由。不另發 ID。
  4. Fast 六問先填；「等待顯示成完成」必須命中等待語意並有去向。
  5. Human verdict 除 attestation 外，要有一行角色／場景（A-5 LIGHT）。

黑名單（dashboard／API 禁詞）不是本 Demo 的牙。錯欄靠對照稿 + 人指，不是詞表。

AC-2 · 發現 vs 裁決標籤

角色：訪談對象。目標：被問「上次怎麼做」時不被錨定。

錯 · 發現題附推薦

上次怎麼追到期？推薦：做 dashboard，因為最低成本。

對 · 先標種類

發現｜上次真的怎麼追到期？講最近一次，不要翻 SOP。

裁決｜在已核「每季漏件」上，選站內清單還是口頭交接？差異：可見 vs 零碼。推薦：先比 no-build。

觀察：題目前綴「發現／裁決」讓後讀者（與靜態牙）看得到種類。推薦只出現在裁決。

AC-9 · Fast 六問

角色：Fast 實作者。目標：進 4-spec 前看過互動風險。

對照案：只改一個狀態字，把「等待法務」顯示成「已完成」。

問命中一句去向
下一步是完成態變成可點下一步升 full
權限否誰能標沒變—
等待語意是把等待顯示成完成升 full
交接否無—
系統外否無—
中斷恢復否無—

六問全否 + 已有 spec + 不改語意純視覺 → 維持 Fast（OC-6）。空白或命中無去向 → 不得當已分診。去向三擇一：升 full／fast+mini／OC 接受風險。
