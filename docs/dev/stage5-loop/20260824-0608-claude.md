## 病灶:唯讀的檢查自己是污染源

第二刀為了「四必填欄的判準是現有 parser,不另寫一套解析」,`load_parser()` 用
`importlib` 真的 import `hooks/devflow-lib.py` 與
`tests/parallel-stage6/contract_ref.py`。**import 預設會寫 `__pycache__`**,於是這支
唯讀檢查每跑一次就在被檢查的樹裡留下兩個檔:

```
hooks/__pycache__/devflow-lib.cpython-312.pyc
tests/parallel-stage6/__pycache__/contract_ref.cpython-312.pyc
```

而 `scripts/test-architecture-guards.sh` 的 `fingerprint()` 收尾要比對的路徑清單裡
**同時含 `hooks/` 與 `tests/parallel-stage6/`**,所以它收尾報「正式 repo 指紋改變了
—— 測試污染了 working tree」。owner 的判讀正確。

關鍵是**兩者的差別**:`hooks/__pycache__/devflow-lib.cpython-312.pyc` 在 main 上本來
就會出現(`scripts/check-spec-gate.sh` 與 `scripts/check-gate-twin.sh` 也 import 同一
支 parser,兩支都在 `test-architecture-guards` 之前跑,所以那份 `.pyc` 落在
`FP_BEFORE` 之內、指紋前後相等)。**`tests/parallel-stage6/__pycache__/` 這個目錄是
第二刀獨有的新東西** —— main 上不存在。那正是本刀相對 main 唯一新增進指紋範圍的檔案。

修法取 owner 給的第一個選項(`sys.dont_write_bytecode`),不取「只對暫存複本
probe」:契約要的是「判準 = **現有** parser」,從真實路徑載入才對得上這句話;
複本會讓 `co_filename` 指到暫存目錄,判準的出處就模糊了。
