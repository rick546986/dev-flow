  **FAIL** —— `assertIn("registration", keys)` 得到 `[]`。

  **ERROR** —— `answer["current_truth"]` KeyError(沒 rebuild,沒有
  current_truth)。同批 4 案合計 **3 FAIL + 1 ERROR**。

  `iter_states` / `iter_knowledge` / `iter_decisions` / `iter_skills` /
  `iter_events`;`project.yaml` 不算。缺世代只在「DB 無鏡射列 **且**

- **測試**:`test_sync.py` 新增 2 案(knowledge / fact)。架構守衛新增

### 2. P1 DATA CONSISTENCY — durable 刷新刪掉 local-only 的檢索索引

- **位置**:`_rebuild_local_once` 開頭 `clear_durable_mirror()` +
  `clear_index()`。前者留下 local-only 列,後者把 retrieval index
  整表清掉;後面只重載 `.dev-flow/`。
- **根因**:既有
  `test_refresh_preserves_local_only_candidates_and_sessions` 只驗
  session / candidate 還在,不驗已入索引的 local-only knowledge
  刷新後還找不找得到。儲存與檢索可見性被拆開,壞的是後者。
- **舊實作下真的紅**:
  `test_refresh_preserves_local_only_knowledge_retrieval` **FAIL** ——
  `store.item(uid)` 刷新後是 `None`。
- **修法**:`store.reindex_local_rows()` 把 durable=0 的
  fact / knowledge / decision / skill / event 依 upsert 同一套
  `index_item` 參數重新入索引。不把列升級成 durable。
- **測試**:上述 1 案。架構守衛釘 `_rebuild_local_once` 必須呼叫
  `reindex_local_rows`。把該呼叫拿掉 → 該項紅。

### 3. P1 RETRIEVAL — CLI `ask` 先消耗 mismatch,新項沒有 embedding

- **位置**:`dev-memory.py` `_resolve()` 對每個指令呼叫
  `ensure_durable_mirror` 且不帶 embedder;`query.execute` 再叫一次
  時世代已對上,`rebuild_local(..., embedder=)` 不會跑。
- **根因**:自動 freshness 只重建列與 lexical index。向量通道依賴
  另一次帶 embedder 的 rebuild,或使用者手動 `reindex`。
  `_resolve` 把「要不要 rebuild」這個事實消費掉了。
- **舊實作下真的紅**:
  `test_cli_ask_embeds_new_durable_item_without_explicit_reindex`
  **FAIL** —— CLI ask 之後新 knowledge 的 embedding 列是 `None`。
- **修法**:`cmd_ask` 用 `_resolve(..., refresh_mirror=False)`。
  `ensure_durable_mirror` 接受 optional embedder 並傳進 rebuild。
  `query.execute` 帶 embedder 做 freshness,並 `embedder.reindex`
  補缺(覆蓋 context 先 rebuild、下一次 ask 世代已對的路徑)。
  不要求呼叫端再跑 `reindex` / `dev-setup`。
- **測試**:上述 1 案,走公開 CLI 子行程,不是只叫 `query.execute`。
  架構守衛釘 `embedder.reindex` + `cmd_ask` 的 `refresh_mirror=False`。
  拿掉 `embedder.reindex` → 該項紅。
