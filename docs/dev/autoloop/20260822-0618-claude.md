## 採納並修好的 finding

### 1. P1 DATA CONSISTENCY — 不可讀 durable 檔被當成可蓋章的缺檔

- **位置**:`memory/agentmem/sync.py` `_snapshot_durable_files` /
  `_generation_of` / `_materialize_snapshot`
- **根因**:`OSError` 被收成 `data=None`,世代雜湊改寫 `b"unreadable"`,
  物化時略過該檔。活樹同一檔仍不可讀 → 兩端雜湊對得上,SQLite 卻少那一筆。
  0518 的「載入位元組 == 活樹」關卡攔不住這條,因為兩邊用同一套合成標記。
- **舊實作下真的紅**:`test_rebuild_fails_closed_on_unreadable_durable_file`
  FAIL — `DurableError not raised`。舊碼把注入的讀失敗當缺檔,蓋了新章。
- **修法**:讀失敗 raise `DurableError`(訊息含 repo-relative 路徑,不含內容)。
  失敗發生在第一次破壞性變更前,舊鏡射與舊章原封不動。
- **測試**:`test_sync.py` +1 案。守衛 +1:
  `不可讀 durable 檔必須 fail-closed`;變異 MEM-33 把 raise 收成
  `data = None` → 紅。

### 2. P1 CORRECTNESS — 破壞性 rebuild 中途失敗後舊章仍有效

- **位置**:`memory/agentmem/sync.py` `_rebuild_local_once` /
  `ensure_durable_mirror`
- **根因**:先 `clear_durable_mirror` / `clear_index`,成功後才寫世代章。
  例外發生在蓋章前,章還是舊的 A;來源退回 A 之後 `stored == current`
  就跳過,半殘或錯代的 DB 被當新鮮。
- **舊實作下真的紅**:`test_failed_rebuild_does_not_keep_old_generation_stamp`
  FAIL — `ensure_durable_mirror` 回 `False`
  (`old A stamp must not bless a DB that was already destroyed`)。
  用既有 `_after_rebuild_read` 縫在蓋章前拋例外,再開一次 store 模擬行程中斷。
- **修法**:`_rebuild_local_once` 在第一次破壞性變更前 persist
  `UNCERTIFIED_GENERATION`(`uncertified`,永遠不是 sha256 hex)。
  下一輪即使來源退回舊世代也會重建。
- **測試**:`test_sync.py` +1 案;既有 never-stabilizes 案改成接受
  `None` 或 `UNCERTIFIED_GENERATION`(意圖仍是「不得蓋對得上的世代」)。
  守衛 +1;變異 MEM-34 拿掉撤章 → 紅。

### 3. P1 RETRIEVAL — 孤兒向量被算到卻當健康,且能餓死有效命中
