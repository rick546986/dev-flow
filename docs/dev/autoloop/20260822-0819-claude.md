## 採納並修好的 finding

### 1. P0 SECURITY — durable writer 跟隨 symlink 目錄寫出 repo

- **位置**:`durable._atomic_write` / `write_knowledge` / `write_state` /
  `write_decision` / `write_skill` / `append_events` / `identity.write_project`
- **根因**:`os.path.abspath` 是字面展開。舊 `_atomic_write` 用
  `makedirs` + `mkstemp` + `os.replace`,全部跟隨 symlink。0717 的
  `_require_regular_or_dir` 只守 snapshot 讀路徑,寫入邊界不存在。
  良性 payload 就能把 YAML 落到 `.dev-flow/knowledge/domain → /tmp/...`。
- **舊實作下真的紅**:7 案 FAIL(`DurableError not raised`)—
  domain / state / decisions / skills / events 各一,
  `.dev-flow` 根對六個 writer 一案,以及
  `_after_write_confine` 在檢查後把祖先換成 symlink 的 race 案。
  正對照 `test_regular_directories_still_write` 在舊實作已綠。
- **修法**:`classify_durable_root` + `_mkdirs_confined` 逐層 `lstat`;
  Linux 走 `O_NOFOLLOW|O_DIRECTORY` dirfd 建暫存並 `os.replace(..., dir_fd=)`;
  無 `O_NOFOLLOW` 時 fallback 在 replace 前再驗一次。違規 raise
  `DurableError`,樹外目錄不變。`write_project` 改走同一支,刪掉
  未禁閉的 `_atomic_write_text`。
- **測試**:`test_durable.py` +8 案。守衛 +1(MEM-39);
  變異拿掉 `_mkdirs_confined` → 紅。
