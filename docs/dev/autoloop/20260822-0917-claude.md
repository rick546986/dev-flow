## 採納並修好的 finding

### 1. P0 SECURITY — writer 禁閉在最終檢查後仍有祖先置換 TOCTOU

- **位置**:`durable._atomic_write_dirfd` / `_open_confined_dirfd`
- **根因**:0819 的 `_after_write_confine` 在第二次 `lstat`/`realpath` **之前**。
  過了那些檢查之後,`_atomic_write_dirfd` 仍用絕對路徑
  `os.open(parent, O_DIRECTORY|O_NOFOLLOW)`。`O_NOFOLLOW` 只守最後一段。
  把中間祖先 `knowledge`(或上兩層 `.dev-flow`)換成指向樹外、且帶真實
  `domain/` 的 symlink,寫入會落到 repo 外。
- **舊實作下真的紅**:2 案 FAIL(`DurableError not raised`)—
  `test_late_ancestor_swap_of_knowledge_cannot_escape`、
  `test_late_ancestor_swap_two_levels_above_parent_cannot_escape`。
  正對照 `test_regular_directories_still_write` 與既有
  `_after_write_confine` 中段 race 案在舊實作已綠。
- **修法**:新增測試縫 `_after_write_validate`(最終檢查之後、開檔之前)。
  `_open_confined_dirfd` 先 `O_NOFOLLOW` 打開 `.dev-flow` 根,再對每一層
  `os.open(component, ..., dir_fd=parent_fd)`。`_atomic_write_dirfd` 不再
  `os.open(parent)`。
- **測試**:`test_durable.py` +2 案。守衛 +1(MEM-42);
  變異把 `_open_confined_dirfd(...)` 換成 `os.open(parent, ...)` → 紅。

### 2. P1 CORRECTNESS — `mirror_revision` 推進是讀再寫,並發會 lost-update

- **位置**:`sync._advance_mirror_revision` / `store.increment_int_meta`
- **根因**:`current_mirror_revision`(獨立 SELECT)+ `set_meta`(另一段
  INSERT/UPDATE)。D-1 之後 DB 是 per-worktree,兩個 `Store` 連線可以同時
  讀到 `R`、都寫 `R+1`。revision 宣稱「這次讀取期間沒有 rebuild 嘗試」,
  lost-update 讓那句是假的。
- **舊實作下真的紅**:`test_two_store_connections_cannot_lose_a_revision_increment`
  FAIL — 兩個執行緒各自開 Store,在 `get_meta(mirror_revision)` 同步後推進,
  回傳 `[2, 2]`(1 != 2)。正對照
  `test_failed_rebuild_consumes_revision_and_invalidates_token` 在舊實作已綠
  (單線仍會先 +1)。
- **修法**:`Store.increment_int_meta` 設 `isolation_level=None` 後
  `BEGIN IMMEDIATE`,同一交易內讀整數、+1、寫回。
  `_advance_mirror_revision` 只呼叫這一支,不再走 `get_meta`+`set_meta`。
  不用行程內鎖。
- **測試**:`test_sync.py` +2 案。守衛 +1(MEM-43);
  變異退回 `current_mirror_revision`+`set_meta` → 紅。

### 3. P1 DATA CONSISTENCY — `classify_durable_root` 把所有 lstat 失敗當 absent

- **位置**:`durable.classify_durable_root` / snapshot / `has_mirrorable_content` /
  `setup.doctor`
- **根因**:`except OSError: return "absent"` 把 ENOENT 與 EACCES/EIO/ESTALE

- **修法**:`FileNotFoundError` 或 `errno.ENOENT` → absent;其餘
  `DurableError("unreadable durable root ...")`。讀寫盤點共用。
- **測試**:`test_sync.py` +7 案(含 2 案正對照)。守衛 +1(MEM-44);
