0001. 外掛併回方法論 repo,兩者不再獨立演進

accepted · 2026-08-13 · 出處:docs/dev/HISTORY.md 的 2026-08-13 · single-plugin-merge;

決策列表md 正本改版歷史

Context

方法論(README、模板、檢查腳本)住在 dev-flow repo;實際在跑的執行程式 (hooks、skills)住在另一個 dev-flow-plugin 目錄。兩邊各自演進,靠一個 「版本握手」機制(devflow-contract.json + runtime-capabilities.json)確認相容。

2026-08-02 的四能力審查明確把「外部外掛併回本 repo」列進防守清單 (= 明確裁定不要做,防止未來有人誤補),理由寫的是: 「握手機制的前提就是兩邊獨立演進。」

十一天後(2026-08-13,commit 7b5d65c)併了。

Decision

併。 外掛的 hooks/、skills/、manifests/、.claude-plugin/ 全部進入方法論 repo, repo 名 = 市集名 = 外掛名統一為 dev-flow;methodology/ 那層子目錄收攏進 repo 根目錄。

握手機制保留不動 —— 它的用途從「兩個 repo 對版」轉為「已安裝到使用者機器上的版本 與採用專案裡的散發副本對版」,那個落差在併 repo 之後依然存在(使用者不會每次都更新外掛)。

Considered Options

選項利弊
維持兩個 repo(2026-08-02 的裁決)兩邊可各自發版;握手機制的語意最單純外掛那個目錄沒有任何遠端,改動進不了版本控制、無法開 PR、無法 review —— 修正只能以 patch 檔暫存(見 notes/patches/README.md);而且方法論改了規則、外掛沒跟上時,兩邊版本永遠對不齊
併成一個 repo(採用)規則與執行它的程式同一次提交、同一個版本號、同一輪 CI;安裝時使用者拿到的一定是配對過的組合使用者安裝外掛時會連稽核紀錄、設計筆記一起下載(repo 即外掛,marketplace.json 的 source: "./" 沒有排除清單);外掛的改動也會綁上方法論的發版節奏

Consequences

換到了什麼:單一版本號、單一 CI、單一 review 動線。原本卡在「無遠端所以無法 review」 的 runtime 修正(F-1 那類)之後可以正常走 PR。

付出了什麼:

  1. 安裝 = 下載整個 repo。 外掛設定的來源是 ./,沒有檔案排除清單,所以 notes/(內部稽核紀錄)也會進到每個安裝者的外掛快取目錄。已於 2026-08-14 確認 owner 接受(repo 本來就是公開的),但這個代價當初沒有被寫下來。
  2. 原裁決的理由沒有被反駁,只是被繞過。 「兩邊獨立演進」確實是握手機制的原始前提; 併了之後握手仍有意義(對的是「安裝版 vs 專案散發副本」),但這個語意轉換 當時沒有寫進任何文件 —— 直到這筆 ADR。
  3. 若日後要把外掛拆回獨立 repo,本筆標記為 superseded,並在 docs/dev/HISTORY.md 追加新的一筆說明原因。不要回頭改這一筆。
