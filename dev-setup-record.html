dev-setup 安裝紀錄(plugin 版)

2026-07-25 初裝(settings hook 版)→ 2026-07-26 升級為 local plugin。目的:單一正本(兩帳號共用 local marketplace 目錄,舊「cp + md5 對檢」紀律退役)、盲原則機械守衛、健康檢查入口。

~/.claude/plugins/local/                 <- local marketplace(兩帳號共用同一目錄)
|- .claude-plugin/marketplace.json       <- 已登錄 dev-talk、dev-flow 兩 plugin
|- dev-talk/                             <- plugin 1(獨立包裝,防耦合)
|  |- .claude-plugin/plugin.json         <- v4.0.0,描述中性
|  |- skills/dev-talk/SKILL.md           <- 訪談引導 v4(單一正本)
|  |- skills/dev-talk/html-shell.html    <- 視覺版殼檔
|- dev-flow/                             <- plugin 2
   |- .claude-plugin/plugin.json         <- v2.0.0
   |- skills/dev-flow/SKILL.md           <- 流程路由器
   |- skills/dev-run/SKILL.md            <- Stage 6 執行引擎(haiku 寫碼-sonnet 審-升階)

   |- hooks/devflow-guard.sh             <- 執行期硬擋(PreToolUse Edit|Write|Read)

~/dev/dev-flow/                          <- 母版文檔(不隨 plugin 走)
|- README.md  _templates/  example/  guide-dev-talk.html  本檔

為什麼拆兩個 plugin:dev-talk 必須看不到任何下游流程字眼(盲原則);包進同一個 plugin 會讓它的 skill 識別名帶上流程前綴。拆開後 dev-talk 自成一包,描述與內容全中性。

② 每件用途

元件用途
dev-talk@local訪談引導 skill(v4:含受影響面清點、五掃複核、⚠️ 高影響決策標記)+ 視覺版殼檔。單一正本,兩帳號同時生效。
dev-flow@local流程路由器 + dev-setup 健康檢查 + guard hook。hook 隨 plugin 啟用自動掛載(不再寫進 settings.json)。
devtalk-guard.sh任何 Edit/Write 後檢查:目標路徑含 skills/dev-talk/ 才動作 → 洩漏掃描(下游階段字眼)→ 命中 exit 2 把錯誤直接回饋給模型要求立即修正。其他路徑靜默放行。
dev-setup skill專案安裝器(install:docs/dev 模板 + .claude/rules/ 骨架 + gitignore;upgrade:只覆蓋 README/_templates,絕不動已產 feature 檔;未識別的外部 workflow artifacts 全數保留)+ 六項健康檢查。
執行守衛
(devflow-exec + guard + prebash + postbash)		Stage 6 起手 devflow-exec.sh start <slug>:驗 4-spec=approved(否則拒啟)→ 從 5-tasks Files 產 scope 快照 + 髒樹基線 → 建旗標。旗標存在時:PreToolUse 擋改 4-spec/1/2/3(契約防篡改+L2 強制停修審)、擋讀 1/2/3(圍欄②)、擋 scope 外寫入(附 L1/L2 提示);PostToolUse Bash 每次指令後 git status 對照 scope,shell 寫入幾秒內被抓。L1 合法出口:allow <file> --reason(留 log + 提醒記 D-n)。stop 撤旗標 → 全部沉睡,其他工作零干擾。
dev-run 引擎派工者(opus/fable5 主對話,不寫碼)逐 T:haiku 執行 → sonnet fresh review → 錯誤升階(haiku→sonnet→opus,同層最多兩次);升階史記 6-notes「執行軌跡」→ 7-review.html 執行記錄表。偏差 L1 保守+記+續走,L2 才停(field guide 模式)。

⑤ 停用 / 移除

停用:兩帳號 settings.json 的 enabledPlugins 把 dev-talk@local / dev-flow@local 設 false(hook 隨 plugin 一起停)。徹底移除:再刪 plugin 目錄與 marketplace.json 內兩個 entry。

⑥ 界線(誠實聲明)

  • 內容硬檢,非權限硬擋 —— dev-talk 的讀寫白名單仍是 prompt 級圍欄(hook 無法得知目前 session 是不是 dev-talk,全域擋寫會誤傷其他工作)。
  • 守得住:dev-talk 的檔案(SKILL/殼檔)被任何 session 改出洩漏字眼 → 立即被抓、回饋要求修正。
  • 守不住:討論進行中的行為偏移(靠 dogfood 盯破盲徵兆)、使用者自己說出下游資訊(設計上不擋)。
  • 執行守衛的殘餘界線(red team 確認,刻意不修):①start 前把 5-tasks Files 寫寬 → 快照照收(緩解:start 會對 src/、docs/ 這類過寬 scope 出警告;5-tasks 若已 commit 過,G3 diff 看得出加寬)②stop → 改 4-spec(保留 status: approved 字串)→ start:目前只驗字串不驗簽章(根治需 G2 核准時寫入內容 hash,列為後續)③shell 圍欄是關鍵字比對,能擋隨手 cat,擋不了刻意混淆 ④跳過步 0 不建旗標 = 全套沉睡。此守衛是紀律輔助工具,不是安全沙箱 —— 對手設定為「想抄捷徑的執行 agent」,不是惡意攻擊者。
  • 改 plugin 內容後,執行中的 session 要 /reload-plugins 才吃到新版。
